§2  OFFLINE — Ingestion

Làm một lần lúc index, nhưng quyết định trần chất lượng cho mọi query về sau.

6 chiến lược chunking

Hierarchical

Mâu thuẫn Day 08: chunk nhỏ retrieve chính xác nhưng thiếu ngữ cảnh; chunk lớn đủ ngữ cảnh nhưng khó match.

Cách làm: match trên child 256 → inject parent 2048 vào LLM.

Late chunking

Cắt trước rồi embed riêng → mỗi chunk mù phần còn lại (“điều này” là gì?).

Cách làm: embed cả doc bằng long-context encoder → pool theo ranh giới chunk.

RAPTOR

Chunk phẳng luôn trả thiếu với câu hỏi tổng hợp xuyên nhiều đoạn.

Cách làm: gom chunk → LLM tóm tắt → cây. Retrieve đúng độ cao: chi tiết ở lá, tổng hợp ở nút cao.

Late chunking vs ContextualLate chunking không gọi LLM cho mỗi chunk → rẻ hơn, nhưng cần encoder long-context (Jina-v3, nomic).

Contextual Embeddings (Anthropic, 2024)

Ghép đoạn mô tả ngữ cảnh vào trước chunk:
“Đoạn này thuộc chính sách nghỉ phép 2026…”

Nhồi cả document mỗi call tốn token → dùng prompt caching. Bổ sung, không thay reranking.

Cấu hìnhLỗi retrieval
Contextual (embed + BM25)↓ 49%

Số liệu Anthropic 2024, tùy corpus. Chi phí: +1 LLM call/chunk lúc index (model rẻ).

Đánh đổiPhải chạy lại mỗi lần re-index (đổi chunking, đổi model). Corpus ngắn hoặc đã rõ thì không cần.

Enrichment Pipeline

Raw chunk→ Summarizationlọc nhiễu, bám ý chính Hypothetical Q&Anối vocab user ↔ tài liệu Metadata extractentity, topic, ngày, nguồn→ Enriched chunk

Tất cả là chi phí one-time lúc index. Dùng model rẻ (GPT-4o-mini, Haiku).

Hypothetical Q&A vs HyDECùng giải quyết vocab gap. Hypothetical Q&A làm OFFLINE (trả tiền 1 lần); HyDE làm ONLINE (+1 LLM call mỗi query).

Matryoshka (MRL) — số chiều là cái núm vặn

Train sao cho 1 vector chứa nhiều vector lồng nhau. Cắt ngắn prefix = nhanh hơn, mất ít chất lượng. Embed 1 lần, dùng nhiều ngân sách.

Cách dùng: 128-d lọc thô (nhanh) → full-d rerank. OpenAI text-embedding-3 hỗ trợ cắt chiều. Đổi cost/latency không cần re-embed.

§3  ONLINE — Retrieval

Chạy lại mỗi query; mỗi vấn đề trong Error Tree có một fix riêng — không bật hết, bật đúng cái cần.

Hybrid + RRF (baseline)

BM25DenseHybrid
Exact keyword✓✗✓
Synonym✗✓✓
Latency<5ms~20ms~25ms

Tiếng Việt: BM25 cần word segmentation (underthesea, VnCoreNLP) trước khi index.

RRF Fusion

score(d) = Σ 1/(k + rankr(d)), k = 60

Không cần training, gộp rank từ nhiều nguồn khác thang điểm. Tinh chỉnh k trong khoảng 10–100.

Vì sao vẫn miss?Câu trả lời nằm ở 1 token hiếm (mã X7-204). RRF gộp rank ở mức document — cần so khớp sâu hơn, ở mức token.

Vượt hybrid — 4 kỹ thuật

Kỹ thuậtÝ tưởngPrecisionLatency
RRF (baseline)Gộp rank, không cần train—~25ms
ColBERT late interaction1 vector/token, MaxSim token↔token; tốn storage multi-vector+8–12%~50ms
SPLADE learned sparseTerm expansion trên inverted index; storage gần BM25+6–10%~40ms
Weighted FusionHọc trọng số (0.3/0.7); cần label data+10–15%~80ms

SPLADE — ví dụ term expansion

BM25: {annual, leave, 12, days}
SPLADE: {annual, leave, vacation, holiday, pto, 12, days}

Query “pto” vẫn tìm thấy. Chi phí: cần GPU lúc index.

ColPali — đừng parse, hãy nhìn

Vision-LLM embed thẳng ảnh trang (patch embeddings) + late interaction. Bỏ qua cả pipeline parse → bảng/biểu/layout giữ nguyên.

Dùng khi: tài liệu nặng layout/bảng/scan — nơi parse luôn hỏng.

Nguyên tắc leo thangMặc định Hybrid + RRF. Chỉ leo lên khi RAGAS chỉ rõ điểm đau: precision tụt → ColBERT · recall do vocab → SPLADE · có label → Fusion · ảnh/PDF → ColPali. Đừng bật hết — mỗi cái thêm latency/storage.

Two-Stage Retrieval — recall rộng → precision hẹp

Retrieverbi-encoder, nhanh→ top-20 → Rerankercross-encoder, chính xác→ top-3 → LLM
ROITốn ~30–50ms/query, đổi lấy +15–25% precision. Nhưng vô dụng nếu chunk đúng chưa được retrieve.

§4  Close the Loop & Limits

RAGAS — 4 metric, 2 trục

Retrieval — lấy đúng chunk chưa?
Context Recall> 0.75
Context Precision> 0.75

Thấp → sửa tầng Retrieve / Rerank.

Generation — trả lời đúng chưa?
Faithfulness> 0.85
Answer Relevancy> 0.80

Thấp → sửa tầng Generate (prompt).

Vì sao tách 2 trụcMột điểm tổng che chỗ hỏng. Tách retrieval vs generation → biết ngay tầng nào mất điểm để tra Error Tree.

Error Tree theo metric

Metric thấpHành động (tầng nào)
Context RecallHybrid (+BM25), HyDE, Multi-Query, metadata filter — Retrieval
Context PrecisionReranking, tăng threshold, metadata filter — Rerank
FaithfulnessPrompt chặt, hạ temperature, citation — Generate
Answer RelevancyCải thiện prompt, mở rộng context — Generate
1. RAGAS baseline→ 2. Bottom-5 fail→ 3. Đọc metric thấp→ 4. Tra bảng → bản đồ→ 5. Sửa → so delta
Thứ tự rẻ → đắtrecall (hybrid) → precision (rerank) → faithfulness (prompt)

4 điểm mù của embedding

Negation“được nghỉ” vs “không được nghỉ” → cosine cao nhưng nghĩa ngược
Temporalchính sách 2024 vs 2026 → cùng score, vector không mã hóa thời gian
Entity“phép nhân viên” vs “phép quản lý” → vector gần nhau, dễ nhầm
Numerical“nghỉ 12 ngày” vs “nghỉ 20 ngày” → cosine cao, nhưng con số mới là đáp án
Kết luậnEmbedding không phải “kém”, mà chưa đủ — một mình nó không phân biệt được phủ định / thời gian / thực thể / con số.
