§1  Tại sao Agent “quên”?

Context window có giới hạn — và hầu hết agent không có bộ nhớ ngoài.

Stateless by default

  • LLM không có persistent state — mỗi API call là một request độc lập.
  • User nói “tôi thích Python” ở session 1 → session 2 agent không nhớ.
  • Conversation dài trên 50 turns → hit context limit.
Lưu ýĐây là vấn đề #1 khi deploy agent thực tế: user kỳ vọng agent “nhớ” — nhưng nó không.

Analogy: bộ nhớ agent giống não người

Não người

Working Memory → consolidation → Long-term Memory

Agent

Context Window → persist facts → External Store

Kết luậnAgent cần cả hai: fast access cho conversation hiện tại + persistent storage cho knowledge qua sessions.

§2  Context Engineering Framework

7 layers of context — quản lý những gì agent “thấy”.

1System ContextPersona, constraints
2Task ContextObjective, instructions
3User ContextPreferences, history
4Memory ContextRecalled facts, episodes
5Retrieval ContextRAG results, documents
6Tool ContextFunction outputs, API responses
7Policy ContextGuardrails, safety rules — trim cuối cùng
Quy tắc trimKhi gần token limit: trim từ dưới lên. Policy context trim cuối cùng — safety không bao giờ bỏ.
Conflict resolutionUser preference mâu thuẫn policy constraint → policy luôn thắng. Cần explicit rules trong system design.

Token budget — phân bổ context window

Short-term 10%
LT 4%
Ep 3%
Se 3%

Tổng 20% cho memory. Phần còn lại dành cho system prompt, task instructions, tool outputs và output generation.

Ngưỡng đỏVượt 20% → context bị nhiễu, accuracy giảm.

§5  Frameworks chuyên dụng & Privacy

Mem0

  • Auto-classify memory types
  • Smart retrieval: relevance + recency ranking
  • Claim: 90% token reduction, 91% faster retrieval
  • API-first, nhanh go-to-market

Zep

  • Entity extraction + progressive summarization
  • Tự build user knowledge graph qua sessions
  • Multi-level summaries: turn → session → cross-session
  • Giảm context size tối ưu

Setup timeNhanh (API)Chậm (build from scratch)
ControlHạn chếFull control
Khi nào dùngMVP, go-to-marketProduction, đặc thù domain

Quyền riêng tư, Bảo mật & GDPR

Privacy-by-Design

Mặc định không lưu PII. User phải explicit opt-in.

Right to be Forgotten

Yêu cầu xóa → xóa tất cả entries → confirm deletion.

Federated Forgetting

Multi-agent: deletion phải propagate tới mọi agent có copy.

Checklist GDPR
  • Data minimization
  • Purpose limitation
  • Storage limitation (TTL)
  • Consent management
  • Deletion verification

§6  Xu hướng 2025–2026

Từ persistent profiles đến file-based identity, heartbeat loops và compiled knowledge bases.

1 · Cross-session memory

Vì sao bùng lên: user không còn chấp nhận agent “mất trí nhớ” sau mỗi thread — với product assistant, sales copilot, tutor, coding agent thì trải nghiệm phải liên tục qua nhiều ngày.

TừSang
Thread-scoped stateUser-scoped memory namespace
Save chat historySave structured facts
Retrieval chỉ dựa similarityscope + recency + relevance + provenance
Write-back cuối phiênHot path + background consolidation
Sai lầm phổ biếnĐem toàn bộ transcript qua session mới → token phình to, recall nhiễu, và rủi ro rò rỉ dữ liệu giữa user tăng mạnh.

Memory record nên có: source, timestamp, confidence, ttl. Namespacing theo user_id, org_id, topic.

Nghiêm trọngMemory gán nhầm user là bug nghiêm trọng. Isolation, TTL, deletion và provenance phải có từ đầu.

2 · Compaction + notes

Vấn đề gốc: conversation dài làm context window bị lấp bởi phần đã “xử xong”. Agent vẫn đọc lại lịch sử, nhưng phần lớn token không còn tạo giá trị.

Recent turns

Hội thoại mới nhất còn đang nóng

Session summary

Trạng thái, quyết định, blockers

Durable notes

Facts/tasks đủ quan trọng → long-term

1. Detect pressuretoken budget / latency→ 2. Summarizedecisions, blockers, next steps→ 3. Extract notesfacts, tasks, prefs→ 4. Rebuild contextsummary + recent turns

Khi nào chạy: chỉ khi gần token limit, khi session kéo dài, hoặc khi chuyển pha từ thảo luận sang thực thi.

BẫySummary có thể mơ hồ hơn transcript gốc. Notes phải ưu tiên trạng thái, quyết định, TODO, constraint — thay vì tóm tắt lan man.

3 · Identity files như control plane

FileVai trò
AGENTS.mdQuy tắc làm việc, workflow, boundaries, coding/execution norms
SOUL.mdIdentity, tone, preferred defaults, behavioral profile
MEMORY.mdNotes bền vững, memory schema, recap các quyết định quan trọng
TASKS.mdOpen loops, backlog, agenda đang theo dõi
Đừng hiểu saiNhững file này không phải retrieval engine: không tự re-rank, không TTL, không conflict resolution, không provenance.
Stack tốt nhấtInstruction files trả lời “hãy cư xử thế nào”; retrieval memory trả lời “nên nhớ điều gì lúc này”. Cần cả hai.

4 · Heartbeat loops

Use case: personal assistant, inbox triage, research copilot, coding agent có backlog dài ngày. Agent được đánh thức định kỳ để compact old context, refresh task list, write safe summaries.

Rủi roHeartbeat + persistent memory khiến prompt injection không chỉ phá một lượt chat mà trở thành memory poisoning hoặc backlog poisoning kéo dài nhiều phiên.
Guardrails tối thiểu
  • Allowlist rõ memory types nào được phép ghi
  • Gắn source, timestamp, confidence cho mọi durable write
  • Tách user request / system rule / agent inference thành các trường riêng
  • High-impact writes phải qua human review hoặc policy check
Nguyên tắcHeartbeat không được tự cho mình thêm quyền — nó chỉ là cơ chế vận hành nền, không phải cánh cửa bypass policy.

5 · Compiled knowledge base (Karpathy “LLM Wiki”)

Plain RAG đủ tốt khiNên nâng lên compiled KB khi
Hỏi đáp 1 lần trên corpus lớn · tài liệu đổi liên tục · chưa cần curate theo entity/timeline/contradiction Câu hỏi lặp lại nhưng vẫn phải retrieval lại từ đầu · cần theo dõi timeline, contradiction, decision history · cần audit trail thay vì chỉ top-k chunks
